## 1. D-SV-1 — Axis-semantics changes do not bump `strategyVersion`

**Decision.** An **axis-semantics change** — a change to what the scorer's axes measure or how the rubric's inputs are computed, made protocol-side under owner governance, with the strategy remaining the same strategy **by the mechanical criterion the registry law itself supplies: the scorer plugin identity (`scorerRef.pluginId`) is unchanged** (`registries/analyst-strategies/README.md:26-27` ties triple-stability to "the analyst's scorer identity — and therefore the triple — is unchanged") — does **not** register a new `strategyVersion`. A `scorerRef.pluginId` change — a different scorer, a wholly different rubric — is a **strategy-identity change** governed by `analyst-strategy-config/v1/README.md:49` (new `strategyVersion`, and across a major, the embedded-major `strategyId` law), never composition movement under the re-record rule. The canonical reference triple `froggy` / `trend_pullback_v1` / `1.0.0` is **frozen through semantic evolution**. Semantics ride the **orthogonal version axes**, each already governed: the UWR profile version for weight or mapping changes ("Any future weight change is a **new profile version** (a new id)", `uwr-profile-pin-v0.1.md:105`); the analysis-plugin **contract version** (and implementation version) for scorer-plugin changes (`afi-config/schemas/analysis-plugin/v1/analysis-plugin.schema.json:52,:58`); the **pipeline version** for topology changes (`afi-config/schemas/pipeline/v1/pipeline.schema.json:49`); and the owner-authorized **`analystConfigHash` re-record under the same triple** for composition movement (`registries/analyst-strategies/README.md:22-28` — the thrice-exercised precedent this ruling ratifies).

The two change-control texts are **reconciled as a governance-ledger fact**: `analyst-strategy-config/v1/README.md:49` governs **strategy-identity changes** — an analyst registering a genuinely different or evolved strategy registers it as a new `strategyVersion` (and, across a major, a new embedded-major `strategyId` per `object-identity-v0.1.md:65-67`); `registries/analyst-strategies/README.md:22-28` governs **protocol-side semantic evolution of the reference strategy**, which re-records under the frozen triple. Neither file is edited; this recorded reading is the authoritative interpretation. The composition-ref doctrine — composition-versioning semantics are deliberately **not** bound to `strategyVersion` (`composition-ref.schema.json:5,:11`) — is ratified as the governing principle.

The frozen triple also preserves standing law rather than straining it: UP-10's scorer-identity pin recognizes the UWR profile only for `froggy` / `trend_pullback_v1` (`uwr-profile-pin-v0.1.md:53,:146`), so semantic evolution under the frozen triple keeps every record inside the pinned recognition, with no re-pin cascade and no partial-bump fail-close hazard (Evidence basis).

**Scope-guard.** A versioning ruling only. It authorizes no semantic change itself; it changes no identity law (OBJ-GOV D-OBJ-3 and the embedded-major rule stand untouched); and it does not disturb what `strategyVersion` bumps remain **for** — genuine strategy-identity changes, which continue to require new registrations under the existing registry law.

## 2. D-SV-2 — The discipline: no silent semantics, eras always distinguishable

**Decision.** The frozen triple is honest only if rubric eras stay tellable-apart. Accordingly, every axis-semantics change MUST: (1) land under its **own bounded accepted decision** (the Part E / DIR-GOV pattern — classification, enumerated program, byte-stability fences); (2) **move at least one orthogonal version surface** it rides on — the re-recorded `analystConfigHash`, a plugin contract version, a **plugin implementation version** (committed to the composition block via `pluginSetHash`, whose members are `{pluginId, pluginVersion, implementationVersion}` per bound plugin — the surface that moves for scorer-implementation changes like the execution-quantisation and ATR-regime filings, per `analysis-plugin.schema.json:58` "an implementation fix that preserves the contract bumps only this"), a profile id, or a pipeline version — so that any two Evidence V3 records scored under different rubric eras differ mechanically in their `composition` block, which both record hashes commit; and (3) regenerate any affected oracle goldens **only** under that decision's bounded authorization with itemized field-level diffs (the D-EV3-8(1)/D-DIR-2(3) convention). A semantics change that would move **no** orthogonal surface is outside this ruling and requires its own classification under E.3; for that subclass, the `strategyVersion` treatment is decided by that filing's own accepted decision — D-SV-1 is neither precedent for nor against it.

**Scope-guard.** Discipline record only; it pre-authorizes no filing, no regeneration, and no change, and adds no new version surface — it binds future filings to the surfaces that already exist.
