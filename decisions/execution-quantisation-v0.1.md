## 3. D-EQ-2 — The quantisation law: threshold map at the grade boundaries

**Decision.** In `afi-core/analysts/froggy.enrichment_adapter.ts`, the quantisation expression at `:184-187` is replaced so that, for a **present** pattern with `patternConfidence` conf (integer 0–100 per the D-FLPR-3 vocabulary):

| Band | `triggerPatternQuality` | Today's grade hitting it |
|---|---|---|
| conf ≥ 75 | **3** | engulfing (75) — was 2 |
| 65 ≤ conf < 75 | **2** | pin bar (65) — **unchanged** |
| 0 < conf < 65 | **1** | inside bar (60) — was 2 |
| conf ≤ 0 | **0** | — |

The **absent** case (`patternConfidence == null`, including the no-candlestick-block path `laneView.ts:93` → `enriched.pattern` undefined → the `: 0` branch) is **retained verbatim** — quality 0, provably leaving the six no-pattern goldens' score bytes untouched. The four bands are exhaustive and non-overlapping over all real confidences in [0, 100] (the adapter's input type is `number`; the governed D-FLPR-3 vocabulary emits integers), monotone, and anchored at the emitted grade boundaries: full three-tier separation of the current grade set plus a present-but-weak tier for any future low-confidence observation, with the pin-bar fixpoint (65 → 2) keeping every committed golden score byte stable. The implementation may extract a named pure helper within the same file; the mapping above is the law, the code shape is not. The `0 | 1 | 2 | 3` output domain, the execution-axis formula (`q/3`, `−0.15`, `clamp01`), and every other adapter read are untouched.

**New unit-test pins (same afi-core PR).** `analysts/__tests__/froggy.enrichment_adapter.test.ts` gains exact-value pins for the mapping table including all boundary values (at minimum conf ∈ {0, 1, 59, 60, 64, 65, 74, 75, 100}, one fractional probe inside the sub-integer band (e.g. 0.8 → 1), and the absent case) — the missing-assertion class that let the collapse ship silently (no existing test asserts any exact `triggerPatternQuality` value; the quantisation is pinned only indirectly today).

**Scope-guard.** Exactly this mapping in exactly this file. If the executing change alters the null branch, the output domain, the execution-axis formula, the scorer, any other adapter read, or any afi-core file beyond the adapter and its test, it must not merge.

## 5. D-EQ-4 — Express scored-value-movement authorization

**Decision.** This filing **expressly authorizes scored-value movement** — the first such authorization on the ledger; no prior clause could be copied because every prior regeneration kept scores byte-identical. The authorized movement is **exactly**:

- **Live signals whose pattern lane detects an engulfing pattern (grade 75):** `triggerPatternQuality` 2 → 3; execution axis `0.6666…` → `1.0` (sweet-spot path) or `0.5166…` → `0.85`; `uwrScore` and `conviction` **+1/12 (≈ +0.0833)**.
- **Live signals whose pattern lane detects an inside bar (grade 60):** quality 2 → 1; execution `0.6666…` → `0.3333…` or `0.5166…` → `0.1833…`; `uwrScore` and `conviction` **−1/12**.
- **Pin-bar and no-pattern signals: no movement** (the 65 → 2 fixpoint and the untouched null branch).
- Derived movement inside `analystScore` prose only where the execution axis crosses the existing 0.4 note threshold (`froggy.trend_pullback_v1.ts:288-290`: inside-bar signals gain the "Trigger pattern quality is low for this setup." axis note) — `axisNotes`/`rationale` are analyst-payload text, not evidence-record members.

The **D-EQ-2 mapping in full is the authorized formula**: its bands away from the emitted grade set (no kernel emits a grade outside {60, 65, 75}, and none emits a non-integer) can move no live record and no committed artifact unless a lane-vocabulary change first lands under its own filing — the enumeration above is therefore exhaustive over reachable inputs. **No committed golden score byte moves** — the movement is proven by the new D-EQ-2 unit-test pins, not by golden movement, and D-EQ-3(3)'s three-field bound is the enforcement. `riskBucket` cannot move (Evidence §1.4). The four axis names, the 0.25 weights, the [0,1] clamps, the UWR profile and its stamp, decay parameters, and `uwrResolvedSource` are untouched (UP-GOV/RC-GOV law). The deterministic provenance golden and its sha256 pin remain byte-identical — **no re-pin is authorized**. Persisted staging records diverge forward per append-once doctrine (MONGO-GOV); the operational analytics plane (`scoring_context`) records the new values as non-normative operational data, no action required.

**Scope-guard.** Movement is bounded to the execution axis via `triggerPatternQuality` under the D-EQ-2 mapping and its 1/12-per-tier arithmetic consequence on `uwrScore`/`conviction`. Any other scored-value movement — any structure/risk/insight axis value, any golden score byte, any riskBucket, any movement from a formula other than the D-EQ-2 mapping — is outside this authorization, and a program producing it must not merge.
